# ReBoxify — Phase 6 Render Deployment & Operations Checklist

Follow these steps in order to deploy `reboxify-api`, `reboxify-worker`, and `reboxify-web` to Render and verify MongoDB Atlas, PayPal Sandbox reconciliation, and live PayPal webhooks. **Never commit real credentials or paste secret values into Markdown or Git.**

---

## 1. Prepare MongoDB Atlas (Replica Set & Network Access)
1. Confirm your MongoDB Atlas cluster is a **replica set** (`mongodb+srv://...` or replica-set seed list with `?replicaSet=...`). Standalone MongoDB nodes are rejected in `NODE_ENV=production` (`503 TRANSACTION_INFRASTRUCTURE_UNAVAILABLE`).
2. Create a dedicated database user with `readWrite` access to the target database (`reboxify`).
3. In **MongoDB Atlas -> Network Access**:
   - Add Render's static outbound IP ranges (if using paid Render static outbound IPs) **or** temporarily allow `0.0.0.0/0` only if using Render dynamic IPs with strong 24+ char random DB credentials and TLS enforced.

---

## 2. Create Render Services via Blueprint (`render.yaml`)
1. Push branch `rebuild/v2-mvp` (once approved) to your Git repository.
2. In **Render Dashboard -> Blueprints -> New Blueprint Instance**, select the repository and branch `rebuild/v2-mvp`.
3. Render will detect [render.yaml](file:///d:/Projects/Reboxify/render.yaml) and create 3 services:
   - `reboxify-api` (Node Web Service, `rootDir: backend`, `buildCommand: npm ci && npm run build`, `startCommand: npm start`, `healthCheckPath: /api/health`)
   - `reboxify-worker` (Node Background Worker, `rootDir: backend`, `buildCommand: npm ci && npm run build`, `startCommand: npm run start:worker`)
   - `reboxify-web` (Static Site, `rootDir: frontend`, `buildCommand: npm ci && npm run build`, `staticPublishPath: dist`, SPA rewrite `/* -> /index.html`)

---

## 3. Configure Environment Variables in Render Dashboard

### A. `reboxify-api` (Backend Web Service)
Auto-set in `render.yaml`:
- `NODE_ENV=production`
- `DEFAULT_CURRENCY=USD`
- `PAYPAL_ENV=sandbox`
- `GEMINI_MODEL=gemini-2.5-flash`
- `JWT_SECRET`, `SESSION_SECRET`, `QR_SIGNING_SECRET` (auto-generated by Render via `generateValue: true` — **never** use `replace-with-...` placeholders)

Set manually in Render Dashboard (`sync: false`):
- `MONGODB_URI`: `<your-atlas-replica-set-uri>`
- `CORS_ORIGIN`: `https://<your-reboxify-web-service>.onrender.com`
- `APP_BASE_URL`: `https://<your-reboxify-api-service>.onrender.com`
- `PAYPAL_CLIENT_ID`: `<sandbox-rest-app-client-id>`
- `PAYPAL_CLIENT_SECRET`: `<sandbox-rest-app-secret>`
- `PAYPAL_WEBHOOK_ID`: `<paypal-sandbox-webhook-id>` *(populate in Step 5 below)*
- *(Optional until Phases 7–8)* `GEMINI_API_KEY`, `ELASTICSEARCH_URL`, `ELASTICSEARCH_API_KEY`

### B. `reboxify-worker` (Background Worker)
Auto-set in `render.yaml`:
- `NODE_ENV=production`, `DEFAULT_CURRENCY=USD`, `PAYPAL_ENV=sandbox`
- `OUTBOX_POLL_INTERVAL_MS=5000`, `RECONCILE_INTERVAL_MS=60000`, `PENDING_RECONCILE_MIN_AGE_MS=120000`
- `WORKER_LEASE_TTL_MS=90000`, `WORKER_MAX_BACKOFF_MS=300000`, `WEBHOOK_MAX_RETRIES=5`
- `JWT_SECRET`, `SESSION_SECRET`, `QR_SIGNING_SECRET` (`generateValue: true`)

Set manually in Render Dashboard (`sync: false`):
- `MONGODB_URI`: `<same-atlas-replica-set-uri>`
- `PAYPAL_CLIENT_ID`: `<same-sandbox-rest-app-client-id>`
- `PAYPAL_CLIENT_SECRET`: `<same-sandbox-rest-app-secret>`
- `PAYPAL_WEBHOOK_ID`: `<same-paypal-sandbox-webhook-id>`
- *(Optional until Phase 7)* `ELASTICSEARCH_URL`, `ELASTICSEARCH_API_KEY`

### C. `reboxify-web` (Frontend Static Site)
- `VITE_APP_CURRENCY=USD`
- `VITE_API_BASE_URL`: `https://<your-reboxify-api-service>.onrender.com`
- `VITE_PAYPAL_CLIENT_ID`: `<public-sandbox-rest-app-client-id>` *(public client ID only — never secret)*

---

## 4. Deploy Backend & Worker and Verify Health Endpoints
1. Trigger deploy of `reboxify-api` and `reboxify-worker` (and `reboxify-web` once `VITE_API_BASE_URL` is known).
2. Inspect **`reboxify-api` Logs**:
   - Confirm `[reboxify-api] MongoDB connected (replicaSet=true).`
   - Confirm `paypalConfigured: true` without printing any credential strings.
3. Inspect **`reboxify-worker` Logs**:
   - Confirm `[reboxify-worker] Starting background worker...` with `mongodbConnected: true`, `replicaSetSupported: true`, `paypalConfigured: true`.
   - Confirm zero startup exceptions or lease errors.
4. Probe `GET https://<your-reboxify-api-service>.onrender.com/api/health`:
   - Expect HTTP **`200 OK`**.
   - Confirm `"status": "ok"`.
   - Confirm `"database": { "connected": true, "replicaSetSupported": true }`.
   - Confirm `"worker": { "status": "HEALTHY", "lastCycleStatus": "OK", ... }`.
   - Confirm `"integrations": { "paypalSandboxConfigured": true, "pickupSchedulerConfigured": false, "bryntumSchedulerMode": "NOT_IMPLEMENTED" }`.
5. Open `https://<your-reboxify-web-service>.onrender.com` in a browser and confirm `SystemStatusBanner` shows green badges for `MongoDB`, `PayPal Sandbox`, and `Worker`, and neutral `Scheduler: NOT_IMPLEMENTED`.

---

## 5. Configure Live PayPal Sandbox Webhooks
1. Log into **PayPal Developer Dashboard -> Apps & Credentials -> Sandbox -> [Your App] -> Webhooks -> Add Webhook**.
2. Set **Webhook URL** to:
   `https://<your-reboxify-api-service>.onrender.com/api/webhooks/paypal`
3. Subscribe to at minimum:
   - `PAYMENT.CAPTURE.COMPLETED`
   - `PAYMENT.CAPTURE.PENDING`
   - `PAYMENT.CAPTURE.DENIED`
   - `PAYMENT.CAPTURE.REVERSED`
   - `PAYMENT.CAPTURE.REFUNDED`
   - `PAYMENT.CAPTURE.REFUND.FAILED`
   - `PAYMENT.CAPTURE.REFUND.DENIED`
   - `PAYMENT.CAPTURE.REFUND.CANCELLED`
   - `CUSTOMER.DISPUTE.CREATED`
4. Copy the generated **Webhook ID** (`WH-...`) and set it as `PAYPAL_WEBHOOK_ID` on both `reboxify-api` and `reboxify-worker` in Render Dashboard, then redeploy/restart both services.
5. Re-check `/api/health` and confirm `"paypalWebhookConfigured": true`.

---

## 6. Post-Deploy Verification Tests
1. **Webhook Signature Verification & Deduplication:**
   - Send a PayPal **Webhook Simulator** test event (or complete a live Sandbox checkout/refund) to `https://<api>/api/webhooks/paypal`.
   - Confirm `200 OK` response and check `webhookEvents` collection in Atlas: `verificationResult: "VERIFIED"`, `processingState: "PROCESSED"` (or `"IGNORED"` for synthetic simulator IDs not linked to an order).
   - Confirm unsigned/tampered POSTs to `/api/webhooks/paypal` return `401` (`WEBHOOK_SIGNATURE_HEADERS_MISSING` or `INVALID_WEBHOOK_SIGNATURE`).
2. **PayPal Reconciliation Verification:**
   - Check `workerLeases` document `reboxify-reconcile-worker` in Atlas: `status: "RUNNING"`, `lastHeartbeatAt` updating every `60s`, `consecutiveFailures: 0`.
   - Confirm any simulated or real `CAPTURE_PENDING` / `REFUND_PENDING` record older than `PENDING_RECONCILE_MIN_AGE_MS` (`120s`) is reconciled cleanly on the next worker cycle without duplicate PayPal calls.
3. **Failure Recovery & Graceful Restart Check:**
   - Trigger a manual restart of `reboxify-worker` in Render Dashboard.
   - Verify logs show `Received SIGTERM, stopping worker gracefully...`, `workerLeases.status` transitions cleanly to `STOPPED`, and the new worker process acquires the lease immediately upon startup without overlapping cycles.
